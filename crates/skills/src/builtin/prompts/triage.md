# Triage

Move issues and external PRs through a state machine of triage roles, categorize, verify, grill if needed, and write agent-ready briefs.

## Roles

Two **category** roles: `bug`, `enhancement`

Five **state** roles: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`

## Process for a specific issue

1. **Gather context** — Read the full issue/PR, parse prior triage notes, explore the codebase
2. **Recommend** — Tell the maintainer your category and state recommendation with reasoning
3. **Verify the claim** — Reproduce bugs, confirm PR diffs do what they claim
4. **Grill (if needed)** — If the request needs fleshing out, grill it into shape
5. **Apply the outcome** — Post agent brief, triage notes, or close with explanation

## Rules

- Every comment posted during triage must start with: `> *This was generated by AI during triage.*`
- A confirmed verification makes a much stronger agent brief
- For `wontfix`: already-implemented points to where it lives; rejected enhancements go to `.out-of-scope/`
- Tickets from `/to-tickets` are already agent-ready — don't triage them
