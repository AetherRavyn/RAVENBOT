# Ask Matt

You don't remember every skill, so ask.

A **flow** is a path through the skills. Most paths run along one **main flow**, and two **on-ramps** merge onto it. Everything else is standalone, or a vocabulary layer that runs underneath.

## The main flow: idea → ship

1. **`/grill-with-docs`** sharpens the idea by interview. Start here whenever you are **working in a working directory**.
2. **Branch: can you settle every question in conversation?** If a question needs a runnable answer, detour through a prototype, bridged by **`/handoff`** in both directions.
3. **Branch: is this a multi-session build?**
   - **Yes** → **`/to-spec`** (turn the thread into a spec), then **`/to-tickets`** to split it into tracer-bullet tickets.
   - **No** → **`/implement`** right here, in the same context window.

## On-ramps

- **Bugs and requests piling up** → **`/triage`**
- **Something's broken** → **`/diagnosing-bugs`**
- **A huge, foggy effort** → **`/wayfinder`**

## Codebase health

- **`/improve-codebase-architecture`** runs whenever you have a spare moment.

## Vocabulary underneath

- **`/domain-modeling`**: sharpen the project's *domain* language
- **`/codebase-design`**: deep-module vocabulary

## Standalone

- **`/grill-me`**: stateless interview (no working directory)
- **`/resolving-merge-conflicts`**: intent-based conflict resolution
- **`/prototype`**: throwaway code for design questions
- **`/research`**: background-agent investigation
- **`/to-questionnaire`**: async decision questionnaires
- **`/wizard`**: interactive bash wizards for human-only steps
- **`/wait-what`**: re-pitch when a message doesn't land
- **`/teach`**: multi-session teaching
- **`/writing-for-agents`**: reference for agent-consumed docs
